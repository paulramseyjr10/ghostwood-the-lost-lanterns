📱 MOBILE RELEASE KIT

This is the playable browser prototype. The information below helps you prepare a mobile release; it does not mean an Android or iPhone app has already been built or tested.

Build and export checklist
  1. Keep this HTML as the self-contained web build and test it on desktop and mobile browsers.
  2. For Android, wrap the web game in a trusted mobile web container or port it to a game engine, then build and test a signed Android App Bundle (AAB) for store submission.
  3. For iPhone, create an iOS project in a supported toolchain on a Mac, configure signing, test on real devices, and archive the app for App Store Connect.
  4. Set the final app identifier, version, icons, launch screen, orientation, touch controls, accessibility, privacy disclosures, and store screenshots before release.
  5. Test on real devices, including pause/resume, backgrounding, performance, safe areas, audio, and all win/lose/restart paths.
Credits and licensing

Game concept and code: original prototype created for this project with AI assistance. Pixel-art visuals: drawn procedurally with canvas shapes; no third-party image pack is intentionally included. Audio: synthesized in-browser using Web Audio; no external audio files included. Fonts: system monospace fonts only.

Before publishing, review the final code and any assets you add, keep a copy of this project’s source, and include accurate credits for any outside libraries, fonts, music, or art you later use. This note is not a legal license or a guarantee of rights clearance.

Store readiness and known limitations
  • Online multiplayer is not implemented; the current two-player mode is local keyboard co-op.
  • The world and obstacle layout are randomized at each restart, so the playfield may vary.
  • Touch movement controls are provided in this prototype, but mobile usability still needs real-device testing.
  • No native Android APK/AAB, iOS archive, store listing, privacy policy, or signed release has been produced yet.
  • Check the current store age-rating, privacy, account, payment, and submission requirements with a parent or guardian before publishing.

Device test checklist
  • Verify smooth movement, level-scaled lantern pickups, portal lock/unlock, smarter wraith chasing, lives, the level-complete panel, defeat, restart, pause, costumes, and map toggle.
  • Check touch buttons on Android and iPhone, including releasing a button when a finger slides away or the app loses focus.
  • Test screen rotation, safe areas, background/resume, performance, and readable text on small screens.
  • Record device model, OS version, pass/fail, and bugs before sharing a test build.
Builds and accounts still needed

Android: use a mobile wrapper or game engine, create a native project, test on an Android device, then build/sign an AAB using Android development tools. A developer account is needed for store distribution.

iPhone: create an iOS project, build and sign with Apple's supported tools on a Mac, test on real devices, and upload a build for TestFlight testing. Apple developer services and signing setup may be required.

Neither platform's installable app is generated by this checklist. Store requirements can change; check the official documentation before submitting.
